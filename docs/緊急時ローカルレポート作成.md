# 緊急時｜ローカルで通常形式のMeta広告PowerPointを作る

## 目的・位置づけ
Streamlitアプリが不調、または複数案件を急ぎで合算したい場合に、既存のレポート集計・PPT生成処理を **Pythonから直接呼び出す** 手順の記録。**共通ツール化はしない**。次回は今回の実例をコピーして必要箇所だけ修正する。既存アプリ・GAS・PPT生成処理には手を加えない。

## 実績（2026-11-16、ユーザーがWindowsローカルで実行し「できた」と報告）
- 対象：本駒込耳鼻咽喉科／2026年10月
- M000103、F000106、A000122（本駒込耳鼻咽喉科（医院紹介））＋ A000290（【再出稿】本駒込耳鼻咽喉科（医院紹介））
- レガシー広告。Meta配信履歴ではなく、キャンペーン名をキーに既存Excelを集計
- 元の実行ファイル：`本駒込_通常レポート生成.py` をリポジトリ直下に置き、`python "本駒込_通常レポート生成.py"` で実行
- 保存用コピー：`tools/本駒込_通常レポート生成.py`（保存場所を `tools/` にしたため、ROOTパスのみ調整。**この保存用コピー自体は未実行・未検証**）

## 次回の使い方
1. ローカルのリポジトリを開き、`tools/本駒込_通常レポート生成.py` を参考に、**別名の単発スクリプト**を作る。保存用の原本は残す。
2. 対象キャンペーン名（`names`）、案件・施設情報（`ad`）、対象年月（`build_month_period`）、正式な配信開始日（`publication_start`）、出力識別子（`report_key`）を対象案件に合わせる。
3. ルート直下の `data/monthly`、`data/monthly_place`、`data/daily_age_gender` に対象期間の既存Excelがあることを確認する。
4. レガシー広告は `services/legacy_report_service.py`、API連携広告は `services/report_service.py` の**既存処理**を使用する。今回のスクリプトはレガシー専用の実例であり、**API連携案件での動作は未検証**。API案件を単純に `データ種別` だけ変更して使わない。
5. PowerPointは `ppt/create_api_ppt.py` の `create_api_meta_report_ppt` を使う。代替レイアウトを新規作成しない。
6. Windows PowerShellで対象スクリプトを `python "ファイル名.py"` で実行。出力PPTを開いて数値・表示期間・スライドを確認する。

## 注意
- 本駒込の実例は `publication_start = date(2026, 1, 1)` を**仮設定**している。累計分析に影響するため、次回は必ず正式な開始日を確認する。
- 複数案件の合算可否・集計単位・重複の扱いは、対象データと既存処理を確認する。特にAPIのリーチ等は安易に足さない。
- 表示ON/OFF設定（`visibility`）は当時の設定を固定したもの。現行アプリの設定と一致するかは必要に応じて確認する。
- 本記録はユーザーのローカル実行成功の報告に基づく。GitHub上の保存用コピーは実行確認していない。
